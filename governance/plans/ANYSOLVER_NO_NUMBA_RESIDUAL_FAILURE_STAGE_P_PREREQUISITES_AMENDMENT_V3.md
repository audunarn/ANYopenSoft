## 5. Complete process and transcript evidence for every outcome

The V2 process safety contract remains binding and is mechanically strengthened:
the runner performs the complete owned-process audit and durable evidence
publication after every outcome, not only timeout.

### 5.1 Prelaunch

Before launch the runner durably publishes the registered `intent.json` and
`process\start.json`, including planned child PID/PGID/session acquisition,
parent PID, argv, cwd, environment, expected exit policy, predecessor receipt,
deadline, and output paths. File and parent-directory `fsync` are mandatory.

The child still uses a fresh session/process group and Linux
`prctl(PR_SET_PDEATHSIG, SIGKILL)` with parent-PID verification before exec.

### 5.2 Outcome classes

The same finalization path must run for all outcome classes:

- normal exit matching policy;
- normal exit mismatching policy;
- diagnostic pytest exit `1` expected by policy;
- timeout;
- launch error before a child PID exists;
- launch error after a PID/PGID/session is partially established;
- signal exit;
- runner-side parsing, payload, transcript, receipt, identity, deadline, or
  exceptional failure.

No outcome may bypass transcript closure or process accounting.

### 5.3 Required `/proc` audit

For every outcome, the runner records an owned-process audit using `/proc` and
the runner's retained identity ledger. It must record:

- direct child PID and start-time identity when one existed;
- owned PGID and session ID when established;
- every observed descendant PID with PPID, PGID, session, process start time,
  executable, command line, and state;
- every member of the owned PGID and session;
- direct child wait/reap result and return status;
- residual descendants, PGID/session members, zombies, inaccessible entries,
  PID reuse conflicts, and all evidence-limited observations;
- a final boolean stating whether zero owned live or zombie processes remain and
  whether termination is fully proven.

On timeout, the bounded SIGTERM/SIGKILL/wait protocol applies only to the owned
process group. On a non-timeout outcome, the runner does not signal an already
terminated group, but it must still wait/reap and audit descendants, PGID,
session, and residuals. On launch error without a child, it records null child
identity and proves no process was registered as owned. Any residual or unproven
state is infrastructure failure.

### 5.4 Durable publication on every outcome

For every normal, timeout, launch-error, signal, and exceptional outcome, the
runner must close, flush, and durably publish:

- `start.json`;
- `transcript\stdout.bin` and `transcript\stderr.bin`;
- `transcript\index.json`;
- `process\start.json`;
- `process\termination.json` with signals/waits even when the list is empty;
- `process\final.json` with the complete `/proc` audit;
- instrument payload partial/final state, including explicit not-started,
  missing, malformed, or preserved-partial truth;
- pytest JUnit state when applicable;
- `result.json` with outcome class, policy match, infrastructure state,
  exception, transcript/process hashes, predecessor receipt, and deadline state.

Every JSON final is produced from its registered unique partial using durable
file flush, atomic rename, and parent-directory `fsync`. Binary transcripts are
created exclusively, flushed, `fsync`ed, closed, hashed, and indexed. If a final
cannot publish, its partial and all earlier evidence remain; the failure is
reported to stderr and never cleaned or retried.

A command becomes an accepted predecessor only when `result.json` is final,
process termination is fully proven, transcript/process evidence is complete,
and its exact expected exit policy matches. Diagnostic nonzero exits retain the
V2 expected-evidence semantics.
