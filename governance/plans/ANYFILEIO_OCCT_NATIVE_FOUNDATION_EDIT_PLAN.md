## 5. Private foundation contracts

### 5.1 Lazy binding boundary

`_binding.py` uses only stdlib and `anyfileio.cad` diagnostics. Neither package
import, backend import, `get_backend()`, nor importing any other foundation
module loads or probes OCP.

An explicit private `_load_binding()` does this exact ordered work:

1. read distribution metadata only for `cadquery-ocp-novtk`;
2. accept only stable numeric versions `>=7.9.3.1.1,<7.10` using a
   zero-padded numeric comparison; reject prerelease/dev/local/nonnumeric
   forms without adding `packaging`;
3. import exact namespace `OCP` through `importlib.import_module`; never import
   or fall back to `cadquery`, `cadquery-ocp`, VTK, or another namespace;
4. return one immutable private binding record containing the exact
   distribution name, observed distribution version, and module handle.

Success and the first terminal missing/version/import failure are each cached
process-wide and thread-safely; later calls return the same binding or re-raise
the same typed `BackendLoadError` with `cad.backend.load_failed` without
re-query/import. A private test-only reset clears only this cache. Distribution
version is **not** runtime OCCT version. This foundation exposes no
`occt_version` and makes no inference; the exact runtime-version API is blocked
pending accepted pinned-wheel evidence in the later reader slice.

### 5.2 Process-global guard

`_locking.py` owns one process-wide `threading.RLock` and private immutable
setting bindings `(name, getter, setter)`. Its context manager:

- checks cancellation before lock acquisition, after acquisition, between
  bounded get/set steps, and after restoration; it never claims interruption
  inside a native call;
- under the lock, snapshots every declared setting before changing any,
  applies overrides in declared order, yields, and restores exact prior values
  in reverse order on success, exception, or cancellation;
- supports same-thread nesting/reentrancy and serializes concurrent threads;
- unwinds partial application in reverse order;
- preserves a primary exception and adds restoration failure notes; without a
  primary exception, restoration failure raises typed
  `cad.backend.load_failed`; and
- any restoration failure atomically and permanently poisons this process-wide
  guard. Every later entry fails with typed `cad.backend.load_failed` before
  any getter, setter, cancellation callback, or native callback. The private
  test reset may clear this poison only for isolated fake tests.

Only actual native/global-setting windows use this guard. Hashing, core record
construction, NumPy processing, filesystem copying, and later Python traversal
must occur outside it. This slice registers no concrete `Interface_Static`
key or OCP getter/setter; those require pinned-wheel call-shape evidence.

### 5.3 Thread-affine resource owner

`_session.py` provides one private resource owner for later XDE sessions. It
records the creator thread, accepts acquired `(resource, closer)` entries, and
offers owner-checked use/close boundaries. Wrong-thread use or close fails
before a closer/native callback with `CadOperationError` diagnostic
`cad.session.wrong_thread` and preserves ownership. Close is owner-thread-only,
reverse-order, and idempotent. It consumes each entry before invoking its
closer, attempts every closer exactly once despite earlier closer failures,
and always ends closed with an empty resource stack. Partial construction and
body failure preserve their primary exception and add every cleanup failure as
a note. With no primary exception, close failures are combined into the
existing `CadOperationError` diagnostic `cad.operation.failed`; no new public
code is introduced. Repeat close and finalization invoke no closer. A finalizer
may emit a `ResourceWarning` only and never calls a closer/OCP. No resource
escapes via a public facade.

The later reader owns concrete `XCAFApp_Application`/`TDocStd_Document`
construction and close semantics after real binding evidence. This foundation
does not create an XDE document or borrow, retain, mutate, rename, or delete a
core-owned source snapshot.

### 5.4 Unit decision

`_units.py` is pure stdlib plus the frozen `LengthUnit` type. It accepts only
canonical `um/mm/cm/m/km/in/ft`, `unknown`, or missing source declarations and
the already-normalized optional override. Frozen metre scales are respectively
`1e-6/1e-3/1e-2/1/1000/0.0254/0.3048`.

The immutable result records declared unit, effective unit, optional
source-to-metre scale, and whether the override supplied missing information.
An override fills only missing/unknown. An explicit declaration/override
disagreement fails; matching declaration/override is accepted without marking
replacement. Missing/unknown without override stays `unknown` with no scale.
No alias parsing, filename/bounds/locale/default inference, STEP/IGES unit
extraction, coordinate mutation, or second scaling occurs here. Later readers
apply the returned scale exactly once to coordinates, translations, and bounds.
